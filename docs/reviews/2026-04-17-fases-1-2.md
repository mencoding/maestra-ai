## P0 — Bloqueiam Fase 3

### P0-1. Path traversal em `snapshot.load()`
**Arquivo:** `packages/maestra-ai/src/maestra_ai/core/snapshot.py:71-83`

`load(snap_id)` aceita `snap_id` direto do CLI (`args.snapshot`) e monta paths sem validação:

```python
path = _snap_dir() / f"{snap_id}.json"  # usuário controla snap_id
```

Vetor: `maestra rollback --snapshot ../../../etc/passwd` → leitura arbitrária. Se combinado com `os.path.join` descuidado, pode haver escrita arbitrária.

**Fix:**
```python
import re
_SNAP_ID_RE = re.compile(r"^[\w:\-]+$")

def load(snap_id: str) -> dict:
    if not _SNAP_ID_RE.match(snap_id):
        raise UserError(f"ID de snapshot inválido: {snap_id}")
    path = _snap_dir() / f"{snap_id}.json"
    # Defesa em profundidade:
    if not path.resolve().is_relative_to(_snap_dir().resolve()):
        raise UserError(f"Path traversal bloqueado: {snap_id}")
    ...
```

**Severidade:** P0 — exploração imediata via CLI.

### P0-2. Vazamento de secrets via `--json` em `MaestraError.where`
**Arquivo:** `packages/maestra-ai/src/maestra_ai/cli/__init__.py:176-182`

```python
err_dict = e.to_human_dict()  # pode incluir where={"client_secret": "..."}
if getattr(args, "json", False):
    print(json.dumps({"error": err_dict}, ...))  # secrets em stdout
```

Em pipelines CI/CD (GitHub Actions), logs ficam públicos. Se algum caller futuro passar `where={"access_token": ...}` ou similar, vaza.

**Fix:** reaproveitar `_SECRET_KEYS` do audit para redact no serializador de erro:

```python
from maestra_ai.core.audit import _redact  # ou mover para core.security
err_dict = e.to_human_dict()
if "where" in err_dict and isinstance(err_dict["where"], dict):
    err_dict["where"] = _redact(err_dict["where"])
```

**Severidade:** P0 — breach de confidencialidade em ambiente multi-tenant.

### P0-3. CircuitBreaker e TokenBucket são in-memory, sem persistência entre processos
**Arquivo:** `packages/maestra-ai/src/maestra_ai/core/ratelimit.py` (todo o módulo)

Singletons por processo. Se CLI for invocado em loop por script externo, ou se `director` daemon entrar em cena (Fase 3+), cada processo tem seu próprio estado. Resultado:
- 2 processos = 120 req/min efetivos (viola rate limit real do Spotify)
- Breaker aberto em P1 não bloqueia P2 → account lockout

**Fix (mínimo):** persistir estado em `state_dir() / "ratelimit.json"` com lock fcntl:

```python
class CircuitBreaker:
    def __init__(self, state_file: Path | None = None, ...):
        self.state_file = state_file or state_dir() / "circuit_breaker.json"

    def _load(self) -> dict:
        if self.state_file.exists():
            with open(self.state_file) as f:
                return json.load(f)
        return {"failures": [], "opened_at": None}

    def _save(self, state: dict) -> None:
        tmp = self.state_file.with_suffix(".tmp")
        with open(tmp, "w") as f:
            json.dump(state, f)
        os.replace(tmp, self.state_file)
```

**Alternativa pragmática:** documentar que CLI é single-process e deferir até Fase 3 (daemon) — mas então P0-3 vira pré-requisito **da** Fase 3, não de v0.2.3.

**Severidade:** P0 para daemon, P1 para uso CLI atual.

### P0-4. JSON parsing sem schema validation em múltiplos pontos
**Arquivos:**
- `core/snapshot.py:77` (`json.load` sem validar que `data["state"]` existe)
- `core/taste.py:22,91`
- `core/context.py:31`
- `cli/feedback_prompt.py:92`
- `cli/playback.py:110`

Arquivo corrompido ou adversarialmente crafted → `KeyError`/`AttributeError` sem tradução para `MaestraError`. Usuário vê traceback cru.

**Fix:** criar helper `core/schema.py` ou validar inline:

```python
def load(snap_id: str) -> dict:
    ...
    data = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(data, dict) or "state" not in data:
        raise StorageError(
            f"Snapshot {snap_id} malformado: ausente 'state'.",
            agent_hint="Arquivo pode ter sido editado manualmente. Restaurar via archive ou deletar."
        )
    return data["state"]
```

**Severidade:** P0 — crashes não tratados quebram contrato `MaestraError` (princípio da Fase 2).

### P0-5. TOCTOU em `fcntl.flock()` — `taste.py` e `context.py`
**Arquivo:** `packages/maestra-ai/src/maestra_ai/core/taste.py:51-78`

```python
with open(lock_path, "w", encoding="utf-8") as lock:  # (1) abre lock
    fcntl.flock(lock, fcntl.LOCK_EX)                   # (2) adquire
    disk_data = self._read_disk_data()                 # (3) lê
# (4) lock liberado ao sair do with → outro processo pode sobrescrever
# depois disso, os.replace() em (66) pode perder a escrita do outro
```

Herdado da Fase 1, sem cobertura de testes de concorrência. Em CLI single-shot atual o risco é baixo, mas vira P0 assim que daemon ou múltiplas sessões `maestra` concorrentes entrarem.

**Fix:** manter lock até após `os.replace()`:

```python
with open(lock_path, "w", encoding="utf-8") as lock:
    fcntl.flock(lock, fcntl.LOCK_EX)
    disk_data = self._read_disk_data()
    merged = self._merge(disk_data, self.data)
    tmp_path = f"{self.path}.tmp"
    with open(tmp_path, "w", encoding="utf-8") as f:
        json.dump(merged, f, indent=2, ensure_ascii=False)
    os.replace(tmp_path, self.path)
    # lock liberado AQUI, após replace atômico
```

**Severidade:** P0 para Fase 3 (daemon), P1 hoje.

## P1 — Dívida com juros altos

### P1-1. Redaction do audit é parcial — evasão de regex possível
**Arquivo:** `packages/maestra-ai/src/maestra_ai/core/audit.py:17-32`

`_SECRET_KEYS` é fechado e só cobre chaves exatas. Não pega:
- `"Bearer eyJ..."` em values stringificados
- Nested em listas: `[{"refresh_token": "xyz"}]` (a lógica atual trata, mas sem teste)
- Chaves como `"authorization"`, `"cookie"`, `"session_id"`

**Fix:** adicionar regex patterns para strings + testes de evasão.

---

### P1-2. Três env vars independentes permitem estado fragmentado
`MAESTRA_DATA_DIR`, `MAESTRA_CONFIG_DIR`, `MAESTRA_STATE_DIR` podem apontar para lugares diferentes. Usuário deleta um dir pensando em "limpar tudo" e perde só parte. Considerar `MAESTRA_HOME` único com subdirs derivadas, ou documentar explicitamente que os três são independentes por design.

---

### P1-3. Race em `_rotate()` de snapshot e audit
Sem lock ao fazer glob + mover arquivos. Dois processos podem duplicar ou perder arquivo no archive. Fix: `FileLock` em `{dir}/.rotate.lock`.

---

### P1-4. `TasteProfile.restore()` não limpa `.tmp` órfão em falha de `os.replace`
Se `os.replace()` falha (disco cheio, permissão), `tmp_path` fica órfão e `self.data` em memória não bate com disco. Fix: `try/except` com cleanup + `StorageError`.

---

### P1-5. Zero testes E2E de CLI
`test_cli_smoke.py` só valida parser. `maestra rollback --snapshot X`, `maestra snapshot create`, `maestra doctor` nunca foram exercitados end-to-end com filesystem real. Risco alto de regressão silenciosa na Fase 3.

**Fix:** adicionar `tests/integration/` com fixtures de fs real + subprocess do CLI.
