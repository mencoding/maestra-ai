## Verificação dos fixes v0.2.3

### P0-1 (path traversal) — RESOLVIDO, com ressalva menor

**Arquivo:** `packages/maestra-ai/src/maestra_ai/core/snapshot.py:15,81-102`

O fix combina (a) regex `_SNAP_ID_RE = re.compile(r"^[\w:\-]+$")`, (b) check `path.resolve().is_relative_to(snap_dir.resolve())`, (c) validação de estrutura (`"state" in data`). Testes em `test_snapshot.py:61-99` cobrem traversal por `..`, por `/`, e malformed.

**Adequação:** `is_relative_to` é o check correto pós-resolução de symlinks. Mesmo que o regex vaze algo estranho, o segundo check segura. Testes são suficientes para o vetor original.

**Ressalvas (não bloqueantes):**

1. **`\w` é Unicode-aware em Python 3** — aceita letras acentuadas, CJK, homoglifos (`Ⅰ`, `А` cirílico, etc.). Não é exploração de path traversal (o `is_relative_to` barra), mas permite IDs visualmente idênticos que colidem com snapshots legítimos. **Fix sugerido:** usar `re.ASCII` ou `re.compile(r"^[A-Za-z0-9_:\-]+$")`.
2. **ID de 1 char passa** (`"a"`). Não explorável, mas um `snapshot.load("")` daria hoje `NotFoundError` (a regex exige pelo menos 1 char, então string vazia falha com `UserError`, ok). Ignorável.
3. **Outros callers de `snap_id` controlado pelo usuário:** verifiquei `cli/rollback.py:44-48` (único consumidor de input externo) — passa `args.snapshot` direto para `rollback.rollback_to(snap_id, …)` que delega a `snapshot.load(target)`. `rollback.py:22` também chama `snapshot.last()` que retorna ID próprio. Não há outros módulos (`history`, `playback`) que aceitem snap_id de usuário — bom.

**Severidade após fix:** nenhum P0 remanescente. Sugestão P2 sobre `re.ASCII`.

### P0-2 (vazamento de secrets em `--json`) — **P0-REGRESSÃO: BYPASS ESTRUTURAL**

**Arquivo primário do fix:** `packages/maestra-ai/src/maestra_ai/cli/__init__.py:176-186`

O fix redacta `err_dict["where"]` antes de `json.dumps`. Isso cobre **apenas** o caminho `raise MaestraError(... where={...})` → `main()` → stdout. Problema: o CLI tem **dois outros caminhos** de erro em stdout/stderr que não passam por `MaestraError` e **não** redactam nada:

#### (a) `cli/_common.py::error()` (linha 48-51)

```python
def error(message, code="ERROR"):
    print(json.dumps({"error": message, "code": code}, ensure_ascii=False), file=sys.stderr)
    sys.exit(1)
```

Chamado por `basic.py` em múltiplos pontos com `str(exception)` do spotipy:

- `basic.py:76`: `error(str(e), "PLAYBACK_ERROR")` para `cmd_play`
- `basic.py:84`: idem para `cmd_pause`
- `basic.py:94`: idem para `cmd_next`
- `basic.py:114,129`: `cmd_queue_add`/`cmd_queue_context`
- `basic.py:151`: `cmd_play_context`

**Vetor:** quando spotipy levanta `SpotifyException` com 401/403, a `str()` dela usualmente contém a URL com query params e, em alguns erros, o header `Authorization: Bearer ...` aparece na representação. Em CI/CD (GitHub Actions), esse stderr vai pros logs públicos. **É exatamente o cenário que P0-2 pretendia fechar.**

#### (b) `except Exception as e: error(str(e), ...)` em basic.py

Captura inclusive `AuthError` do spotipy (status 401) que **é** `MaestraError` — deveria ir pro handler em `main()` com redact, mas é engolido em `basic.py` e jogado cru em stderr.

#### (c) `cli/_build_deps` (`__init__.py:118-123`)

```python
except Exception as e:
    raise AuthError(f"Falha ao conectar com Spotify: {e}") from e
```

O `f"...: {e}"` embute `str(e)` no `what_happened_msg`. O redact em `main()` não toca `what_happened` — só `where`. Se `str(e)` contém token, vaza.

**Fix proposto (consolidar redact num único ponto):**

```python
# core/security.py (novo módulo)
from maestra_ai.core.audit import _redact

_SECRET_RE = re.compile(r"(Bearer\s+[A-Za-z0-9\-_\.]+|[A-Za-z0-9]{32,})")

def redact_str(s: str) -> str:
    return _SECRET_RE.sub("REDACTED", s)

def redact_error_dict(d: dict) -> dict:
    d = dict(d)
    for field in ("what_happened", "title"):
        if isinstance(d.get(field), str):
            d[field] = redact_str(d[field])
    for field in ("where", "body"):
        if field in d:
            d[field] = _redact(d[field]) if isinstance(d[field], (dict, list)) else redact_str(str(d[field]))
    return d
```

E em `cli/_common.py::error()`:

```python
def error(message, code="ERROR"):
    from maestra_ai.core.security import redact_str
    print(json.dumps({"error": redact_str(message), "code": code}, ensure_ascii=False), file=sys.stderr)
    sys.exit(1)
```

**Ação adicional:** trocar `except Exception: error(str(e), …)` em `basic.py` por `raise SpotifyAPIError(str(e)) from e` — deixa o handler unificado tratar, e só aí o redact roda.

**Severidade:** **P0-regressão**. O fix atual resolve o caso de teste escrito (`test_cli_main.py:9-37`), mas o teste **prova apenas o caminho de `MaestraError.where`** — não testa `error()` nem `except Exception`. Cobertura de teste tautológica.

### P0-4b (schema em taste/context/feedback_prompt/playback) — **PARCIALMENTE RESOLVIDO**

Todos os quatro arquivos citados no review anterior receberam `try/except (json.JSONDecodeError, OSError)` + `isinstance(data, dict)`.

**Adequação para os arquivos listados:** ok. Corrupção agora degrada para estado vazio em vez de traceback cru.

**Problemas:**

1. **Degradação silenciosa** — `taste._load()` retorna `_empty_profile()` quando o arquivo está corrompido. Usuário **perde o perfil de gosto inteiro sem aviso**, e a próxima `save()` sobrescreve o disco com o vazio. Isso é pior que o crash original: o crash era ruidoso; agora é silencioso e destrutivo. **Fix:** mover o arquivo corrompido para `taste_profile.json.corrupt.<ts>` antes de voltar ao vazio, e logar warning em stderr.

   ```python
   except (json.JSONDecodeError, OSError):
       corrupt = f"{self.path}.corrupt.{int(time.time())}"
       try:
           os.rename(self.path, corrupt)
       except OSError:
           pass
       print(f"AVISO: taste_profile corrompido movido para {corrupt}", file=sys.stderr)
       return self._empty_profile()
   ```

2. **Três `json.load*` ficaram fora do fix:**

   - `core/storage.py:55` — `read_config()` faz `json.loads(p.read_text(...))` sem try/except. Config corrompido → traceback cru em `doctor check_config`, `auth setup`, e qualquer caller de `_build_deps`. **Severidade:** P1 (quebra `doctor`, que é a ferramenta de recuperação).
   - `core/storage.py:97` — `load_refresh_token()` idem. Se `token.json` está corrompido (edição manual, disco intermitente), `load_refresh_token` crasha com `JSONDecodeError` em vez de retornar `None`. **Severidade:** P0 — rompe fluxo de reauth.
   - `core/playback_processor.py:64` — `json.loads(line)` dentro de loop sobre linhas de `playback_events.jsonl`. Uma linha malformada (por exemplo: append atômico interrompido) aborta processamento inteiro sem retorno. **Severidade:** P0 — blindpoint no pipeline de sinais contextuais, usado pelo director em loop.

**Severidade agregada:** **P0-parcial.** O review anterior listou 5 pontos e os 5 pontos listados foram fechados — tecnicamente o P0-4 está feito. Mas a **auditoria completa de `json.load*`** expõe 3 pontos equivalentes que ficaram.

## P0 remanescentes (reavaliação)

### P0-3 (ratelimit in-memory) — **AGRAVADO**

O `director run` é invocado como processo filho separado do CLI principal via `subprocess.Popen(start_new_session=True)` em `cli/director.py:79-83`. Portanto:

- CLI invocado pelo usuário + director rodando em background = **dois processos, dois buckets, dois circuit breakers**.
- Se usuário roda `director start --interval 60` e depois faz várias chamadas manuais, total pode exceder 60 req/min real do Spotify.

**Não é Fase 3 futura — é estado atual.** Severidade real hoje: **P0.**

**Fix concreto recomendado:** SQLite com `PRAGMA journal_mode=WAL`. Alternativa: `fcntl.LOCK_EX` + JSON atômico com `time.time()` (wallclock) para timestamps persistidos.

### P0-5 (TOCTOU em locks) — **PARCIALMENTE MAL DIAGNOSTICADO no review anterior**

Releitura do código: `taste.save()` (linha 60-74) **está correto** — `os.replace` dentro do `with fcntl.flock`. Análise anterior leu mal.

**Persistem P0:**

- **`context.py::set()`** não tem lock. Dois processos concorrentes podem truncar arquivo.
- **`playback.py::_save_state()`** escreve sem lock nem atomic-replace. Director em loop + CLI manual = corrupção.
- **`feedback_prompt.py::mark_prompted()`** idem.
- **`playback._append_events()`** — append text line-by-line sem lock. POSIX garante atomicidade só até PIPE_BUF (4KB). Rarear, mas existe.

**Fix:** helper `core/storage.py::atomic_write_json(path, data)` com lock + tmp + replace.

**Severidade:** P0 para os três primeiros (director daemon vs CLI manual). P1 para `_append_events`.
